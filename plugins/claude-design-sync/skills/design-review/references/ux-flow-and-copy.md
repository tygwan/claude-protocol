# UX flow and copy review

## User, role, and moment

State who is acting, what they are trying to do, what they know, and what emotional or operational context matters.

Do not merge the needs of different roles into one screen. A child, caregiver, clinician, administrator, purchaser, and operator may need different wording and detail even when they see the same underlying event.

## Task flow

Map:

1. trigger,
2. expectation,
3. decision point,
4. action,
5. system response,
6. recovery or next task.

Look for:

- loops that repeat without new information,
- steps that appear after the user can no longer act,
- hidden prerequisites,
- premature technical detail,
- dead ends,
- branching that changes policy implicitly,
- loss of work or state,
- a safe exit that is visually or semantically missing.

## Copy truth

Interface copy must describe what is known now.

Avoid unsupported promises about:

- time,
- age,
- stage,
- eligibility,
- automatic unlock,
- saved results,
- success,
- clinical outcome,
- future availability.

If the system knows only that an action is unavailable, do not invent why. If a named decision owner has approved a reason, present it to the correct audience at the right detail level.

## Error versus state

Ask whether the user caused an input error, the system failed, or the product is reporting a valid state.

- Input error: identify the item and explain correction.
- System failure: acknowledge failure and provide recovery or safe exit.
- Valid restriction: explain availability without blame or technical codes.
- Policy decision: show only approved meaning; flag missing policy.

Styling and language must agree. Neutral copy inside an alarming red error treatment still reads as failure.

## Cognitive load

Check:

- one decision per moment where possible,
- essential explanation before action,
- secondary detail on demand,
- short labels with supporting context,
- repeated facts removed,
- unfamiliar terminology explained,
- numbers and codes hidden unless they help the current role act.

## Trust and emotional safety

Do not use reassurance that contradicts reality. Avoid blame, shame, coercion, false urgency, or false celebration.

For vulnerable audiences, verify:

- failure language,
- perceived rejection,
- responsibility attribution,
- who receives technical details,
- whether a blocked task is closed gracefully,
- whether results or progress are represented truthfully.

## Recommendation test

A copy recommendation should state:

- the fact it communicates,
- the action it enables,
- the audience,
- the unsupported interpretations it avoids.
