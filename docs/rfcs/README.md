# RFCs

Design proposals for the Claude Design Sync protocol. An RFC captures a structural decision and its open questions before implementation, so the shape can be reviewed and debated without a large code change under review at the same time.

Each RFC records: status, target, base branch, related roadmap items, and the decision it proposes.

| RFC | Title | Status |
|---|---|---|
| [001](001-frontend-quality-intelligence.md) | Frontend Quality Intelligence | Draft (request for comments) |
| [002](002-extensible-report-contract.md) | Extensible Report Contract | Draft (request for comments) |

## Lifecycle

1. **Draft**: proposed, open for comments. No implementation merged.
2. **Accepted**: the structure is agreed. Implementation proceeds in separately reviewed PRs.
3. **Superseded**: replaced by a later RFC, which names the one it supersedes.

An RFC does not implement anything by itself. It is a request for structural consensus.
